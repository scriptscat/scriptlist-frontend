# 移动端访问体验优化（前台 + 管理后台）

> Status: Draft
> Owner: scriptlist-frontend
> Last updated: 2026-11-17

**Objective:** 手机（宽度 < 768px，下称「窄屏」）访问前台和管理后台时，所有页面都不出现横向溢出，文字不会一字一行，导航和操作都能触达。

**Hard invariant:** 桌面端（≥ md 768px；详情页沿用现有 ≥ lg 1024px 双栏）布局与交互不变；7 个语种、深浅两套主题都要成立。

对照稿（本地证据，非约束）：`.dev-kit/artifacts/2026-11-17-mobile-experience/mockups/index.html`。「现状」是 main 79d5f65 在 iPhone 13 视口（390×844）下真实运行的截图，「改后」是在同一页面里注入 CSS/DOM 得到的效果。

## Problem

以下均为 2026-11-17 在 390px 视口实测（已验证）：

1. **窄屏没有导航入口。** 头部导航 `Menu` 在 md 以下整个隐藏（`src/components/layout/MainLayout/index.tsx:178`），手机上进不了「脚本列表 / 社区 / 浏览器扩展」。「发布脚本」在 sm 以下也是隐藏的（`:194`）。主题和语言只有两个 24×24 的小图标。
2. **脚本卡片挤压变形。** 搜索页、用户主页（脚本 / 收藏）、收藏夹详情共用 `ScriptCard`，它的底栏把下载数、更新时间、分享和标签（限宽 40%）塞在一行。窄屏下「8,866,925」断成两行，「下载」「4 天前」一字一行，标签竖排；作者名在用户主页里一字一行。
3. **用户主页卡片层层嵌套。** 页面卡片、筛选卡片、脚本卡片三层边框和内边距叠加，脚本卡片只剩约 300px。
4. **反馈列表行的元信息在词中间折断。** #75 之后已经没有横向溢出，但「· 更 / 新于 5 个月前」仍会在词中间换行；外层卡片和列表框的内边距也叠在一起。
5. **版本页分页说明一字一行。** 「第 1-10 项，共 240 个版本」与页码挤在一行，被压成一个字宽的一列，还溢出到页脚。
6. **详情页头部占满首屏，并且「收藏」被截断。** 窄屏下头部信息、安装 / 关注 / 收藏按钮、「数据统计」是分开的三块，描述挤在 64px 图标右侧的窄列里。另外，按钮行里「收藏」两个字被 `min-w-0 truncate` 截掉，线上只显示「☆ ꟾ 129」。
7. **管理后台在窄屏基本不可用。** `AdminLayout` 的侧栏固定 220px 宽，内容区只剩约 80px：表格被压到约 40px，标题和表单一字一行。17 个表格组件、所有管理页都受影响。

## Actors and user stories

1. 作为**手机上的访客或用户**，我想打开导航、切换主题和语言、发布脚本，以便不用回到电脑上也能使用全站功能。
2. 作为**手机上的访客**，我想在列表、详情、反馈、版本页上一眼读懂信息，不需要左右拖动，也不会看到一字一行的文字。
3. 作为**用手机处理事务的管理员**，我想在管理后台切换页面、浏览列表、执行操作，同时不会误触删除或封禁这类危险操作。

## Design decisions

| # | 决定 | 依据与放弃的方案 |
|---|---|---|
| 1 | 窄屏导航用 ☰ 打开右侧抽屉，主题和语言也收进抽屉 | 用户确认。放弃：主题和语言留在头部 —— 两个 24px 图标点击区域太小，头部也放不下 |
| 2 | 详情页头部用方案 B「与列表卡片同款」 | 用户在 A / B 对照中选定 B。放弃：A「一体化卡片」—— 与列表卡片的视觉不一致 |
| 3 | 管理后台表格在窄屏改为每行一张卡片 | 用户选定。放弃：表格横向滑动 —— 改动小，但手机上读起来吃力 |
| 4 | 所有管理表格共用一种卡片结构，每个页面只声明列到卡片位置的映射 | 17 个表格保持一致，规则只写一处。放弃：每页手写卡片 —— 规则会分叉，工作量是 17 倍 |
| 5 | 卡片操作：不超过 2 个时全部显示；超过 2 个时只显示第一个安全操作，其余收进 ⋯；危险操作永远不当主按钮（不用实心主样式）。一行只有危险操作时，直接露出为红色描边按钮 | 移动端防误触。用户选定「仅危险操作直接露出、红色描边」。放弃：照搬表格那一排按钮 —— 脚本管理有 5 个操作，一行放不下；仅危险操作也收进 ⋯ —— 多点一下 |
| 6 | 主操作一律取现有操作顺序里的第一个安全操作：脚本管理普通行是「修改可见性」，已删除的行是「恢复」 | 用户对「按顺序露出」回复「可以」，并选定已删除行用「恢复」。放弃：把「AI 审核」提到主位；已删除行固定为「修改可见性」 |
| 7 | 管理卡片上的时间用相对时间（如「3 小时前」），点按显示完整时间 | 用户确认，与前台一致。放弃：沿用表格的「11/17/2026, 2:28:37 PM」格式 |
| 8 | 反馈列表只修元信息折行和内边距叠加，行结构沿用 #75 | #75 已在 main 上重做了这个列表。放弃：重新设计列表行 |
| 9 | 方案 B 的底栏同时保留「更新于」和「创建于」，只在「 · 」处换行 | 现在「创建于」只出现在头部（`ScriptDetailClient.tsx:808`），不能在窄屏丢掉。放弃：只保留更新时间 |
| 10 | 只在表头上的筛选和排序，窄屏改为卡片列表上方工具栏里的下拉框，效果与表头一致 | 用户选定。放弃：窄屏不提供 —— 手机上就无法按这些条件找数据 |
| 11 | 「窄屏不横向溢出」的自动检查只覆盖本次改动的页面 | 用户选定。放弃：覆盖所有路由 —— 会把 spec 未涉及的页面一起拉进来，范围明显扩大 |

## 前台

### 顶部导航（窄屏）

- 头部从左到右是 logo、登录按钮（已登录时为通知铃铛和头像）、☰。主题切换和语言图标在窄屏不再显示于头部。
- 点击 ☰ 从右侧打开抽屉。抽屉内依次是：首页、脚本列表、社区（外链，带外链标识）、浏览器扩展（外链）、「发布脚本」主按钮（仅登录后显示）、外观三段切换（浅色模式 / 跟随系统 / 深色模式）、语言选择。
- 当前所在页面对应的导航项高亮。外观和语言的选择结果与桌面端现有切换行为一致。
- 按 Esc、点击遮罩或点击任一导航项后，抽屉关闭。抽屉打开期间焦点锁在抽屉内，关闭后焦点回到 ☰。☰ 带有可读标签，并通过 `aria-expanded` 反映展开状态。
- md 及以上保持现有的横向导航，不显示 ☰。

### 脚本卡片（窄屏）

- 标签从底栏移到描述下方单独一行，可以换行，仍最多显示 3 个加「+N」。
- 底栏一行显示「⤓ 下载数 下载」「更新时间」和右侧的分享按钮，不再折行。
- 版本号与作者并排；作者名只占一行，过长时用省略号截断。今日安装单独一行。
- md 及以上保持现状。

### 用户主页（窄屏）

- 「我的脚本 / 我的收藏」容器和筛选区不再画自己的边框与内边距。脚本卡片直接贴满内容宽度。筛选下拉框排成一行，放不下时横向滚动。

### 反馈列表（窄屏）

- 每行的元信息（「#id · 作者 创建于 … · 更新于 …」）只在「 · 」处换行，每一段内部不断开。
- 外层卡片的内边距收窄到 12px。

### 版本页（窄屏，< sm）

- 分页不显示「第 x-y 项，共 N 个版本」；页面顶部已经有同样的统计。页码居中，不换行。

### 详情页头部（< lg，方案 B）

- 头部卡片：左侧 48px 图标；右侧依次是名称（可换行）和右上角的评分「☆ 4.7」，然后是「版本标签 + 作者」一行，再是绿点加「近 24 小时 +N」一行。
- 卡片下半部分依次是：简介（整宽，默认 3 行，带「展开 / 收起」）、标签（整宽，可换行）、底栏「⤓ 总安装量 · 更新于 … · 创建于 …」（只在分隔符处换行）。
- 窄屏不再显示单独的「数据统计」卡，因为它的三项数据已经放进头部。桌面右侧栏的统计卡不变。
- 安装 / 关注 / 收藏 / ⋯ 操作区仍在头部卡片下方。修复「收藏」被截断：标签文字不收缩，「关注」按内容宽度，剩余宽度都给「收藏」。在 390px 宽下，「关注 160」「收藏 129」都完整可见。
- 库（`type === 3`）同样使用新头部，操作区维持现状（库本来就没有安装按钮组）。

## 管理后台

### 外壳（窄屏）

- 侧栏隐藏。内容区顶部显示一个按钮「☰ 管理后台 / 当前页名称 ▾」；当前页在子菜单里时，显示为「父项 · 子项」，例如「AI 审核 · 审核记录」。
- 点击这个按钮，从底部弹出完整的管理菜单（含子菜单），当前页高亮。选择菜单项后跳转并关闭菜单；也可以按 Esc 或点击遮罩关闭。焦点行为与前台抽屉相同。
- 外层卡片内边距收窄到 12px。页面标题和工具栏各占一行。工具栏里的搜索框占满一行。筛选项可以换行，但「标签：控件」始终在同一行。

### 列表卡片（窄屏，覆盖全部 17 个表格组件）

每个数据行渲染为一张卡片，结构如下：

1. **标题行**：标题是主字段，可点击时保留链接，最多 2 行；反馈内容最多 3 行。标题右侧是该行的状态 / 类型标签，标签可以换行，最多占卡片宽度的 45%。有图标的页面（OIDC 提供商）在标题前显示图标。
2. **副信息行**：「#ID · 副信息」，单行，超长时截断。
3. **正文**（仅评分管理有）：评价内容，最多 3 行。
4. **次要字段**：两列键值（字段名灰色、值在右）。值可以是原来单元格里的控件，比如脚本审核的开关，交互保持不变。
5. **底栏**：左侧是相对时间（点按显示完整时间），右侧是操作。操作规则见决定 #5：
   - 不超过 2 个时全部显示，安全操作在最右的主位。
   - 超过 2 个时，主位只放第一个安全操作，其余收进 ⋯ 菜单。危险操作（删除、封禁、移除等）放在菜单最底部，前面加分隔线，并用红字显示。
   - 危险操作在任何情况下都不用实心主按钮样式。一行只有危险操作时（如反馈、评分、两张白名单表），直接显示为红色描边按钮。
   - ⋯ 菜单里的项需要确认时，用确认对话框，标题与表格里的确认文案相同；直接显示的按钮沿用表格现有的确认方式。
   - 操作的确认弹窗和权限判断与现有表格完全一致。

各页面的列映射（标题 / 副信息 / 标签 / 次要字段 / 时间 / 主操作）：

| 页面 | 标题 | 副信息 | 标签 | 次要字段 | 主操作 |
|---|---|---|---|---|---|
| 用户管理 | 用户名 | #ID · 邮箱 | 状态、管理员等级 | 注册 IP | 修改等级（另有封禁） |
| 脚本管理 | 脚本名称 | #ID · 作者 | 状态、可见性、类型 | 趋势分、评分系数 | 修改可见性 + ⋯（已删除行为「恢复」+ ⋯） |
| 举报管理（脚本 / 内容） | 脚本或被举报内容 | #ID · 举报人 | 状态、原因 | 评论数 | 查看 |
| 反馈管理 | 反馈内容 | #ID · 客户端 IP | 原因 | — | 无主操作；删除为红色描边按钮 |
| 脚本审核 | 脚本 | #ID · v版本 · 提交者 | 状态 | 脚本审核状态（开关） | 审核 |
| AI 审核记录 | 脚本 | #ID · 模型 | 状态 | Tokens、耗时、理由 | 详情 |
| 相似度（相似对等 5 个子表） | 脚本 A ↔ 脚本 B（或该表的主对象） | #ID | 状态、较早方 | Jaccard、共同指纹、完整性评分等数值列 | 详情 |
| 评分管理 | 脚本 | #ID · 用户 | 评分 | 正文：评价内容 | 无主操作；删除为红色描边按钮 |
| 公告管理 | 标题 | #ID | 状态、级别 | — | 编辑（另有删除） |
| 广告管理 | 素材 / 标题 | #ID | 状态、类型 | 广告位、权重、排期时间、曝光 / 点击 | 编辑（另有删除） |
| OAuth 应用 | 应用名称 | — | 状态 | 客户端 ID（可复制）、回调地址 | 编辑 + ⋯ |
| OIDC 提供商 | 名称（带图标） | — | 状态、类型 | 发行者 URL、客户端 ID | 编辑（另有删除） |

对照稿里没有逐一截图的子表（相似度的嫌疑脚本、完整性警告、两张白名单表，以及内容举报）按同一规则映射：标题取该表的主对象名称，数值和说明列放进次要字段。

- **表头筛选与排序**：只放在表头上的筛选和排序（脚本管理的状态筛选和排序、脚本审核、广告管理、相似对的排序等），在窄屏改为卡片列表上方工具栏里的下拉框。选中后的数据与在桌面表头上做同样选择的结果一致，翻页时保持当前条件。
- **状态**：加载中显示卡片形状的骨架；空列表沿用现有空状态；请求失败沿用现有错误提示与重试。
- **分页**：窄屏只显示页码，不显示「共 N 条」和每页条数选择。
- **桌面端**：md 及以上仍是原来的表格，排序、筛选、分页行为都不变。

## 无障碍与 i18n

- 抽屉和底部菜单：有焦点锁、支持 Esc 关闭、关闭后焦点回到触发按钮，触发按钮带 `aria-expanded`。⋯ 按钮带可读标签（「更多操作」）。卡片内的所有操作都能用键盘访问。窄屏下新增的可点击元素，点击区域不小于 32×32。
- 新增文案（例如打开 / 关闭菜单、外观、语言、管理后台、更多操作、展开 / 收起）先写 `zh-CN`，再补齐其余 6 个语种。

## Out of scope

- 后端接口改动（本次只改前端）。
- 代码页 Monaco 的窄屏换行和可读性。
- 页脚、面包屑的点击区域。
- 管理后台表单页（系统配置等）的表单内部布局；表单页只获得外壳上的改动。
- 管理后台表格在桌面端的任何变化。
- spec 未涉及、但可能在窄屏横向溢出的页面：审计日志、脚本管理页的权限 / 分组 / 日志、用户设置（OAuth、Passkey）、邀请页、已处理脚本列表，以及系统配置、全量扫描、相似对详情等表单 / 详情页。它们不在本次修复范围内，也不在自动溢出检查之内。
